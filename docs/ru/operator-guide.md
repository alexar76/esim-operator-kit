# Гайд оператора

Гайд ведёт от пустого сервера до первой продажи, а затем описывает ежедневную работу: заказы,
возвраты, баланс, бэкапы, обновления. На настройку заложите час. Большая часть этого часа уходит на
ожидание оптового аккаунта и DNS-записи.

Другие документы: [обзор](../../README.ru.md) · [гайд для агентов](agent-guide.md) · [онбординг](rails.md) · [интеграции](integrations.md) · [SDK](sdk.md)

## Короткий путь

Когда сервер, домен и оптовый аккаунт готовы (разделы 2–4), остальное делает одна команда, в демо-режиме:

```bash
git clone https://github.com/alexar76/esim-operator-kit.git && cd esim-operator-kit
./onboard.sh            # витрина, узел продавца для агентов, узел федерации; спрашивает только недостающее
./onboard.sh --hub      # то же со своим хабом: own-hub.md
```

Она спросит домен, название магазина, идентификатор ваших предложений и ключи оптовика (ввод скрытый, ключи пишутся в `secrets/` и нигде не печатаются). Потом запустит всё в демо-режиме, дождётся HTTPS, проверит узел продавца, запишет `node.toml`, прогонит ту же проверку допуска, что проведут другие хабы, и спросит, прежде чем вступить в федерацию. После неё остаются платёжные адреса и ключи (раздел 8), `DEMO_MODE=0` и тестовый заказ (раздел 10). Запускайте её снова после любых изменений: она делает только то, чего не хватает. `./onboard.sh --check` ничего не меняет и показывает, что готово. Разделы ниже — то, что она делает, для тех, кто предпочитает руками.

**На портах 80 и 443 уже работает nginx или другой веб-сервер?** Команда это заметит и спросит. С nginx она встанет за ним: опубликует сервисы кита на `127.0.0.1` (`docker-compose.override.yml`, Caddy кита не запускается), напишет сайт для вашего домена и получит сертификат через certbot — каждый шаг после вопроса. С любым другим сервером она напечатает маршруты, которые нужно добавить. Выбор запоминается в `PROXY` в `.env`.

## 1. Что вы поднимаете

```text
            https://esim.example.com
                      │
                   Caddy (80, 443, Let's Encrypt)
      ┌───────────────┼──────────────────────────────┐
      │               │                              │
   store          rails (/agents/*)              node (/.well-known/ai-market.json, /ai-market/*)
 покупают люди   покупают агенты по x402        хабы находят ваши предложения
      │               │
      └──── ваш баланс в eSIM Access ────┘     платежи идут на ваши кошельки
```

- **store** — сайт: страницы стран, оплата, страница заказа с QR-кодом.
- **rails** — узел продавца для ИИ-агентов: бесплатные предложения, платные заказы по x402.
- **node** — это `aimarket node`. Он сообщает хабам AIMarket, что вы продаёте, чтобы агенты вас нашли. Запускайте его последним, когда всё остальное работает.
- **Caddy** получает и продлевает HTTPS-сертификат и раздаёт запросы трём сервисам.

store и rails покупают с одного оптового аккаунта. Ни один из них не держит деньги: покупатели
платят на ваши адреса, а кит только читает сети, чтобы увидеть поступление.

## 2. Перед началом

| От $50 на балансе | Первое пополнение — минимум $50 (карта, PayPal или Alipay; банковский перевод — от $3000). |

| Адреса кошельков | EVM (один адрес на все семь EVM-сетей), Tron, Solana, TON. Подойдёт любой набор. |
| Условия продажи и политика конфиденциальности | Две публичные страницы. eSIM Access ждёт, что сайт каждого реселлера на них ссылается. |
| Необязательно: ключ Coinbase Developer Platform | Включает USDC в Base без газа для людей и заказы агентов по x402. Шаг 8. |
| Необязательно: Stripe | Включает карты. Шаг 8. |

## 3. Оптовый аккаунт

1. Зарегистрируйтесь на [esimaccess.com](https://esimaccess.com) и подтвердите почту.
2. Пополните баланс (в консоли: баланс, затем пополнение). Минимум — $50. Каждая проданная eSIM оплачивается с этого баланса по оптовой цене, так что это ваш товарный запас, а не комиссия.
3. Откройте раздел разработчика (API) в консоли. Там два значения: **AccessCode** и **SecretKey**. Обращайтесь с SecretKey как с паролем.

Песочницы нет: каждый заказ через API настоящий. Два способа проверить дёшево:

- Закажите самый дешёвый тариф (несколько десятков центов) и отмените неиспользованный профиль. Неиспользованные профили возвращаются на баланс.
- До первого пополнения попросите в поддержке небольшой тестовый кредит: Customer Support, затем Submit ticket, тип «Top Up». Объясните, что подключаете API и вам нужно несколько долларов на тестовые заказы.

## 4. Сервер и домен

1. Создайте A-запись домена на IPv4-адрес сервера. Проверьте со своего компьютера:

```bash
dig +short esim.example.com
```

2. Установите Docker на сервер ([docs.docker.com/engine/install](https://docs.docker.com/engine/install/)) и проверьте, что compose работает:

```bash
docker compose version
```

3. Откройте порты 80 и 443 в файрволе сервера и в панели хостинга. Let's Encrypt проверяет порт 80, прежде чем выдать сертификат.

## 5. Скачайте кит и настройте его

```bash
git clone https://github.com/alexar76/esim-operator-kit.git
cd esim-operator-kit
cp .env.example .env
nano .env
```

| Настройка | Что указать |
|---|---|
| `DOMAIN` | Ваш домен, без `https://`. |
| `STORE_NAME` | Название, которое покупатели видят в шапке, заголовке и в окне кошелька. |
| `PRODUCT_ID` | Короткий идентификатор ваших предложений в федерации, например `esim-mytravel`. Буквы, цифры, дефисы. |
| `STORE_CONTACT` | Почта, на которую пишут покупатели. Показывается в подвале. |
| `STORE_TERMS_URL`, `STORE_PRIVACY_URL` | Ваши условия продажи и политика конфиденциальности. Ссылки стоят в подвале. |
| `MARGIN_PCT` | Наценка на оптовую цену в процентах. `100` удваивает цену. |
| `MIN_MARGIN_USD` | Минимальная наценка на одну eSIM в долларах. К дешёвым тарифам добавляется не меньше этой суммы. |
| `PRICES_FILE` | Необязательно: ваш прайс-лист поверх формулы, `/config/prices.csv`. См. ниже. |
| `DEMO_MODE` | `1` — баннер и никаких платежей. `0` — продажа. Держите `1` до шага 10. |
| `PAY_TO_EVM`, `PAY_TO_TON`, `PAY_TO_TRON`, `PAY_TO_SOLANA` | Ваши адреса для приёма. Пустая строка выключает сеть. |
| `EVM_CHAINS` | Какие EVM-сети предлагать, номерами сетей: `8453` Base, `1` Ethereum, `42161` Arbitrum, `10` OP, `137` Polygon, `56` BNB Chain, `43114` Avalanche. |
| `EVM_RPC_<номер сети>`, `SOLANA_RPC` | Необязательно: ваши RPC-адреса. У публичных есть лимиты запросов. |
| `SUPPLIER` | Откуда берутся eSIM: `esimaccess` (по умолчанию), `airalo`, `esimgo` или `http` для вашей собственной системы. См. [интеграции](integrations.md). |
| `WEBHOOK_URL`, `WEBHOOK_SECRET_FILE` | Необязательно: статус каждого заказа, с подписью, в вашу CRM, биллинг, Telegram или таблицу. См. [интеграции](integrations.md). |
| `REFUND_KEY_FILE`, `REFUND_MAX_USD`, `REFUND_DAILY_MAX_USD` | Необязательно: автоматические возвраты агентам за неиспользованные eSIM из выбранного вами кошелька. См. [кейсы](cases.md). |

**Как считается цена.** Цена = опт × (1 + `MARGIN_PCT`/100), но не меньше опт + `MIN_MARGIN_USD`. Округление — вверх до цента. С настройками по умолчанию (100 % и $1.00) Франция 1 ГБ на 7 дней стоит $0.70 оптом и продаётся за $1.70. Тариф на 20 ГБ за $9.00 оптом продаётся за $18.00. Розничные eSIM-магазины обычно берут $4–8 за маленькие тарифы, так что запас есть.

**Свой прайс-лист.** Если у вас уже есть розничные цены или для каких-то стран нужна другая наценка, задайте их прайс-листом. Тарифы, которых список не касается, считаются по формуле выше.

```bash
cp config/prices.example.csv config/prices.csv
nano config/prices.csv                   # затем раскомментируйте PRICES_FILE=/config/prices.csv в .env
docker compose run --rm rails node bin/esim-rails.mjs prices /config/prices.csv
```

Пример:

```csv
match,gb,days,price_usd,margin_pct,min_margin_usd
TR,1,7,4.50,,
TR,,,,80,
JP,,,,,2.00
global,,,,60,
US_0.1_7,,,off,,
```

| Колонка | Что означает |
|---|---|
| `match` | Какие тарифы: id предложения (`TR_1_7`, как в ответе на запрос цены), страна (`TR` — собственные тарифы этой страны), `region` или `global` (многострановые тарифы) или `*` (все тарифы). |
| `gb`, `days` | Необязательно, рядом со страной, `region`, `global` или `*`: только тарифы такого объёма и срока. `gb` совпадает с точностью ±10 %: поставщики считают гигабайт как 1000 или 1024 МБ. |
| `price_usd` | Фиксированная цена, например `4.50`, или `off` — тариф не продаётся. |
| `margin_pct`, `min_margin_usd` | Или формула с этими числами для выбранных тарифов. Пустое значение берётся из `.env`. |

Побеждает самая точная строка: id предложения важнее страны, страна важнее `region` и `global`, они важнее `*`, затем строка, где заполнено больше из `gb` и `days`; из двух одинаково точных — та, что выше. Фиксированная цена никогда не продаёт в убыток: если оптовая цена поднимется выше неё, тариф считается по формуле, пока вы не поправите список, и проверка цен на шаге 7 об этом скажет. Файл читается при старте; список с ошибкой останавливает запуск и называет номер строки, так что опечатка не продаст по цене, которую вы не задавали. Экспорт из таблиц подходит: точки с запятой и десятичные запятые читаются. Если цены живут в вашем биллинге, выгружайте их в этот файл по расписанию. Применить изменения: `docker compose restart store rails`.

**Только адреса.** Каждый `PAY_TO_*` — адрес, на который вы принимаете. Киту никогда не нужен приватный ключ или сид-фраза. Если инструкция или человек просит положить их в `.env`, это ошибка.

## 6. Положите ключи

Ключи лежат в `secrets/`, по одному значению в файле. Папка исключена из git и монтируется в контейнеры только для чтения. Введите значения так, чтобы они не попали в историю команд:

```bash
cd ~/esim-operator-kit
umask 077
printf 'AccessCode: '; read -rs v; printf %s "$v" > secrets/esimaccess_access_code; echo
printf 'SecretKey: '; read -rs v; printf %s "$v" > secrets/esimaccess_secret_key; echo
unset v
```

Контейнеры работают от пользователя 1000, поэтому отдайте ему файлы ключей и папки данных:

```bash
mkdir -p data/store data/rails data/node data/caddy
sudo chown 1000:1000 secrets/*
sudo chown -R 1000:1000 data/store data/rails data/node
ls -l secrets
```

Сама папка остаётся вашей, так что файлы можно добавлять и позже. Каждому новому файлу ключа нужны те же `sudo chown 1000:1000` и `chmod 600`.

В [secrets/README.md](../../secrets/README.md) перечислены все необязательные файлы: ключ CDP, ключи tonapi и TronGrid, ключи Stripe.

## 7. Запуск в демо-режиме

```bash
docker compose up -d --build
docker compose ps
docker compose logs --tail 30 store rails
```

Первая сборка занимает несколько минут. Затем проверьте три вещи:

```bash
curl -s https://esim.example.com/agents/healthz
curl -s -X POST https://esim.example.com/agents/quote -H 'content-type: application/json' \
  -d '{"country":"FR","min_gb":3,"min_days":7,"limit":3}'
```

- Проверка здоровья отвечает `"ok":true` и показывает число предложений, у eSIM Access их около 1700. `"demo":true` пока ожидаемо.
- Запрос предложений возвращает настоящие тарифы по вашим ценам.
- `https://esim.example.com/` показывает вашу витрину с демо-баннером. Откройте страну и пройдите оплату: каждый шаг оплаты отвечает «Демо-режим: оплата отключена».

Если проверка отвечает `"ok":false`, оптовые ключи неверны или не читаются. См. раздел 14.

**Проверьте цены.** Команда печатает баланс и лучшие предложения по любым странам по вашим ценам, рядом с каждым — оптовая цена. С прайс-листом она показывает ещё, что посчитала каждая строка и какие строки не нашли ни одного тарифа:

```bash
docker compose exec -T rails node scripts/catalog.mjs FR ES IT US JP TH
```

Поменяйте `MARGIN_PCT` или `MIN_MARGIN_USD` в `.env` и примените: `docker compose up -d`. После правки прайс-листа: `docker compose restart store rails`.

## 8. Платежи

Каждый способ включается, когда задан его адрес (и ключ, где он нужен). Включите те, которыми
пользуются ваши покупатели. USDT в Tron — самый частый способ платить криптой; за ним идут USDT и USDC в EVM-сетях и USDT в TON.

| Способ | Что задать | Как платит покупатель | Как витрина подтверждает |
|---|---|---|---|
| USDC в Base без газа | `PAY_TO_EVM` + `secrets/cdp_api_key.json` | Подписывает одно сообщение в браузерном кошельке и не платит за газ. | Подпись проводит фасилитатор CDP. Сначала выдаётся eSIM, потом проводится платёж; при неопределённом результате требуется сверка. |
| USDC / USDT в 7 EVM-сетях | `PAY_TO_EVM` (+ `EVM_CHAINS`) | Отправляет перевод из браузерного кошелька или из любого кошелька или биржи и вставляет хеш транзакции. | Читает квитанцию: перевод этого токена вам, не меньше цены, новее заказа. Ждёт подтверждений: 3 в Ethereum и BNB Chain, 10 в Polygon, 1 в остальных. Одна транзакция оплачивает один заказ. |
| USDT в Tron | `PAY_TO_TRON` (+ `secrets/trongrid_key`) | Отправляет ровно указанную сумму, из TronLink на странице или из любого кошелька. | Каждый заказ просит цену плюс несколько миллионных долларов (не больше $0.0099 сверху). Эта точная сумма и опознаёт заказ среди ваших подтверждённых переводов USDT. |
| USDC в Solana | `PAY_TO_SOLANA` (+ `SOLANA_RPC`) | Открывает ссылку Solana Pay или сканирует её QR-код (Phantom, Solflare, Backpack). | У каждого заказа свой ключ-референс, кошелёк добавляет его в перевод. Витрина находит транзакцию по нему. |
| USDT или TON в TON | `PAY_TO_TON` (+ `secrets/tonapi_key`) | Подключает Tonkeeper или другой кошелёк через TON Connect либо платит вручную с указанным комментарием. | Находит перевод по комментарию заказа через tonapi.io. |
| Карты | `secrets/stripe_secret_key` + `secrets/stripe_webhook_secret` | Stripe Checkout. | Вебхук Stripe. |

Отправленный платёж (все способы, кроме Base без газа и карт) ищется в течение 24 часов после
создания заказа.

**Ключ Coinbase Developer Platform.** Он включает USDC в Base без газа для людей и заказы агентов по x402. Без него витрина всё равно принимает USDC в Base обычным переводом, но узел для агентов заказы не принимает.

1. Войдите на [portal.cdp.coinbase.com](https://portal.cdp.coinbase.com) и создайте проект.
2. API Keys: создайте секретный API-ключ и скачайте его JSON-файл.
3. Скопируйте файл в `secrets/cdp_api_key.json` (в нём `id` и `privateKey`), затем выполните `sudo chown 1000:1000 secrets/cdp_api_key.json && sudo chmod 600 secrets/cdp_api_key.json` и `docker compose up -d`.

**Stripe.** В панели Stripe добавьте вебхук `https://<ваш домен>/api/stripe/webhook` с событиями `checkout.session.completed` и `checkout.session.async_payment_succeeded`. Секретный ключ (`sk_live_…`) положите в `secrets/stripe_secret_key`, а секрет подписи вебхука (`whsec_…`) — в `secrets/stripe_webhook_secret`.

**Лимиты запросов.** Публичных TronGrid, tonapi и RPC хватает небольшому магазину. Когда продажи станут регулярными, добавьте бесплатный ключ TronGrid и ключ tonapi, а `EVM_RPC_<номер>` и `SOLANA_RPC` направьте на своего провайдера.

## 9. Агенты и федерация

Узел rails уже отвечает агентам по адресу `https://<ваш домен>/agents/`. Чтобы агенты находили вас
поиском на хабе, опишите узел для федерации и анонсируйте его.

1. Сгенерируйте `node.toml` из живого каталога. Подставьте своё название, домен и `PRODUCT_ID`:

```bash
docker compose exec -T rails node scripts/node-toml.mjs \
  --name "My Travel eSIM" --url https://esim.example.com \
  --product esim-mytravel --upstream http://rails:9490 > node.toml
head -20 node.toml
```

2. Запустите узел:

```bash
docker compose --profile federation up -d --build node
curl -s https://esim.example.com/.well-known/ai-market.json | head -c 400; echo
```

3. Проверьте его так, как проверит хаб, и анонсируйте:

```bash
docker compose exec node aimarket doctor --url https://esim.example.com
docker compose exec node aimarket node knock --config /node/node.toml --hub https://modelmarket.dev
```

Перед тем как внести вас в каталог, хаб вызывает `esim.quote` с настоящей страной. После этого агент, который ищет на хабе «eSIM France», получает ваши предложения. Оплата никогда не идёт через хаб: агент платит вашему узлу по x402, прямо на ваш кошелёк.

В `data/node/` лежит ключ подписи узла — это его идентичность в федерации. Сделайте бэкап. Повторите пункт 1, когда в каталоге появятся новые страны.

**Подтверждённые доставки.** Каждый заказ и каждый возврат, на которые отвечает ваш узел, несут квитанцию, подписанную ключом продавца (`data/rails/provider_ed25519.pem` — тем ключом, которым подписан каждый бесплатный ответ), а `node.toml` из шага 1 публикует его открытую часть как `provider_pubkey`. Покупатель, который нашёл вас через хаб, может принести в этот хаб квитанцию и её транзакцию; хаб проверяет обе ончейн и засчитывает подтверждённую доставку. Тогда в ваших листингах появляется `deliveries_30d` (доставки и возвраты, подтверждённые покупателями за 30 дней, и сколько среди них разных покупателей), а оценка доверия хаба к вам засчитывает один успех на каждого разного покупателя. Сверх шага 1 делать ничего не нужно; в `node.toml`, записанном до 15 октября 2026 года, ключа нет — повторите шаг 1. Сохраните ключ продавца в бэкапе вместе с остальным `data/rails/`: квитанции, подписанные потерянным ключом, больше не совпадут с вашим листингом. В [кейсах](cases.md), кейс 3, это показано на настоящих покупателях.

Проверьте, что ключ опубликован:

```bash
curl -s https://esim.example.com/ai-market/v2/manifest | grep -o provider_pubkey | head -1    # provider_pubkey
```

Для этого в образе `node/` нужен `aimarket-hub` 3.15.27 или новее — его кит и ставит. Узел старее ключ отбрасывает, и тогда хаб отвечает на квитанции ваших покупателей `404`.

**Свой хаб вместо узла.** `./onboard.sh --hub` запускает на вашем домене целый хаб: он сам выставляет ваши предложения, даёт агентам ваш собственный адрес для поиска и MCP и федерируется с другими хабами. Если раньше работал узел, идентичность домена сохраняется. Подробно: [свой хаб](own-hub.md).

## 10. Тестовый заказ и запуск продаж

1. В `.env` поставьте `DEMO_MODE=0` и ещё раз сверьте адреса `PAY_TO_*` символ за символом.
2. Примените:

```bash
docker compose up -d
curl -s https://esim.example.com/agents/healthz
```

Должно быть `"demo":false`. `"paid_orders":true` появляется, когда заданы ключ CDP и `PAY_TO_EVM`.

3. Купите самый дешёвый тариф какой-нибудь страны в своей витрине, своим кошельком, но не с адреса самой витрины, в той сети, которой, по-вашему, чаще всего будут платить покупатели. QR-код должен появиться на странице заказа в течение минуты. Не платите с самого кошелька `PAY_TO_EVM`: фасилитатор x402 отклоняет оплату с адреса на него же (`self_send_not_allowed`).
4. Проверьте платёж в кошельке и заказ в консоли eSIM Access.
5. Если eSIM вам не нужна, отмените неиспользованный профиль в консоли eSIM Access. Оптовая цена вернётся на баланс. Ваш платёж всё равно ушёл на ваш же кошелёк.

Так же проверьте канал агентов: нужен небольшой тестовый кошелёк с долларом USDC в Base (не ваш
`PAY_TO_EVM`). Команда запрашивает предложения, показывает цену и платит только с `--yes`:

```bash
cd rails && node examples/agent-buy.mjs https://esim.example.com/agents TR --key-file ~/test-wallet.json --yes --refund
```

В файле ключа лежит `{"private_key": "0x…"}`, и он никогда не печатается. В ответе будут eSIM
(`esim_tran_no`) и транзакция проведения в Base. `--refund` сразу просит деньги назад: узел отменяет
неиспользованную eSIM у поставщика (себестоимость вернётся на баланс) и, если возвраты включены
([кейсы](cases.md), раздел 7), возвращает деньги тестовому кошельку; если нет — возврат записывается как
причитающийся. Когда хаб внесёт вас в каталог, запустите то же самое с `--hub https://modelmarket.dev`
вместо вашего адреса: это путь, которым идут агенты, вместе с квитанциями. В [гайде для агентов](agent-guide.md)
разобран настоящий запуск, вместе с отказом.

Повторите для каждой включённой сети. После этого вы в деле.

## 11. Ежедневная работа

**Заказы.** Витрина хранит их в `data/store/orders.json`. Список тех, что требуют вашего внимания:

```bash
sudo jq -r '.[] | select(.status=="refund_due" or .status=="underpaid")
  | [.created_at, .id, .status, .method, (.price_cents/100), .payment.ref, (.payment.payer // "-"), (.error // "")] | @tsv' \
  data/store/orders.json
```

| Статус | Значение | Что делать |
|---|---|---|
| `awaiting_payment` | Заказ создан, денег пока нет. | Ничего. |
| `delivered` | Оплачен, eSIM у покупателя. | Ничего. |
| `refund_due` | Оплачен, но оптовик не выдал eSIM: кончился баланс или тариф сняли с продажи. | Верните деньги покупателю на `payment.payer` в той же сети или пополните баланс и продайте ему тариф вручную. |
| `underpaid` | Пришло меньше цены. | Верните платёж или попросите покупателя доплатить и выдайте вручную. |
| `expired` | За 24 часа ничего не пришло. | Ничего. Платёж, пришедший позже, не сопоставляется: вы увидите его в кошельке без заказа. |

Покупатели пишут на `STORE_CONTACT`. Просите у них номер заказа из адреса страницы (`/o/<номер>`). Не просите полную ссылку: в ней их токен.

**Баланс.** Держите оптовый баланс выше продаж за несколько дней. Когда его не хватает на заказ, оплата пишет «Тариф временно недоступен» и не берёт деньги. Проверить баланс:

```bash
docker compose exec -T rails node scripts/catalog.mjs | head -1
```

**Логи.**

```bash
docker compose logs -f --tail 100 store rails
```

В логах никогда нет кодов активации и ключей.

**Бэкапы.** Ежедневно сохраняйте `data/` и `secrets/` куда-нибудь вне сервера:

- `data/store/`: заказы. Потеряете их — страницы заказов у покупателей перестанут работать.
- `data/rails/`: заказы агентов, ключ их статус-токенов и ключ подписи узла. Обе папки хранят ещё последний каталог (`catalog-snapshot.json`): если поставщик перестанет отвечать, он отдаётся до шести часов, а в демо-режиме — сколько потребуется.
- `data/node/`: идентичность в федерации.
- `data/hub/`: ваш собственный хаб, если он есть: его ключи, база, настройки и токен администратора.
- `data/caddy/`: сертификаты. Их можно выпустить заново, но бэкап избавит от лимитов Let's Encrypt.

**Обновления.**

```bash
git pull
docker compose up -d --build
docker compose --profile federation up -d --build node    # если запускаете узел федерации
```

Читайте заметки к выпуску, прежде чем обновлять магазин, который продаёт.

## 12. Заказы агентов

Агенты покупают через `POST /agents/order` (см. [гайд для агентов](agent-guide.md)). Узел проверяет платёж x402, покупает профиль и проводит платёж только после того, как профиль создан. При неопределённом результате профиль сохраняется для сверки; повторно списывать деньги нельзя. Заказы агентов записываются в `data/rails/orders.json`, без кодов активации. USDC приходят на `PAY_TO_EVM` в сети Base.

**Возвраты.** Агент может попросить возврат за eSIM, которую не устанавливал: `POST /agents/refund` с номером eSIM и статус-токеном. Узел отменяет eSIM у оптовика, который возвращает деньги на ваш баланс, и возвращает цену на адрес, с которого платили. Выплата автоматическая, только если вы дали узлу кошелёк возвратов (`REFUND_KEY_FILE`, с лимитами `REFUND_MAX_USD` и `REFUND_DAILY_MAX_USD`); без него возврат записывается как причитающийся, и вебхук `agent_order.refund_due` сообщает, что его нужно оплатить. Настройка, правила и реальный возврат с транзакциями — в [кейсах](cases.md).

## 13. Законы, налоги и условия

Это не юридическая и не налоговая консультация. Прежде чем продавать, спросите бухгалтера в своей стране.

- **Продавец — вы.** Покупатели покупают у вас, на ваших условиях. eSIM Access — ваш поставщик. Возвраты, поддержка и налоги — ваши.
- **Условия и конфиденциальность.** eSIM Access ждёт, что на вашем сайте опубликованы условия продажи и политика конфиденциальности. Задайте `STORE_TERMS_URL` и `STORE_PRIVACY_URL`. В условиях опишите возвраты (установленную eSIM обычно вернуть нельзя), совместимость устройства (разблокированный телефон с поддержкой eSIM) и момент начала действия.
- **НДС в ЕС.** Телекоммуникационные услуги потребителям облагаются в стране покупателя. Единое окно OSS (One-Stop Shop) позволяет декларировать все страны ЕС одной декларацией. Вне ЕС правила другие.
- **Крипта.** Можно ли принимать криптовалюту и как её учитывать, зависит от вашей страны. Храните записи заказов: у витрины есть сеть, транзакция и сумма каждого платежа.
- **Персональные данные.** Витрина ничего не спрашивает у покупателей: ни имени, ни почты. Она хранит заказ (тариф, цена, способ) и платёж (транзакция и адрес плательщика). Адрес в блокчейне всё же может считаться персональными данными по GDPR, так что упомяните его в политике конфиденциальности.

## 14. Решение проблем

| Что видно | Причина | Что делать |
|---|---|---|
| Браузер говорит, что сертификат недействителен | DNS ещё не указывает сюда или закрыт порт 80 | `dig +short <домен>`, откройте порт 80, затем `docker compose restart caddy` и смотрите `docker compose logs caddy`. |
| `healthz` показывает `"ok":false` или на витрине нет стран | Оптовые ключи неверны или пользователь 1000 не может их прочитать. В логах `catalogue not loaded yet: <code>`. | `sudo rm secrets/esimaccess_*`, запишите их заново, как в шаге 6, затем `docker compose restart store rails`. |
| В логах `EACCES` или `permission denied` | Папки данных принадлежат не пользователю 1000 | `sudo chown -R 1000:1000 data/store data/rails data/node` |
| Оплата пишет «Тариф временно недоступен» | Оптового баланса не хватает на тариф | Пополните eSIM Access. |
| Каждый платёж отвечает «Демо-режим: оплата отключена» | `DEMO_MODE=1` | Шаг 10. |
| Сети нет в оплате | Её `PAY_TO_*` пустой | Проверьте `.env`, затем `docker compose up -d`. |
| Витрина перезапускается снова и снова | Какой-то `PAY_TO_*` — неверный адрес: с ним витрина отказывается стартовать | `docker compose logs store` назовёт его. Исправьте `.env`. |
| Платёж в Tron не найден | Сумма была не точной, часто потому что биржа вычла из неё свою комиссию | Найдите перевод в кошельке и верните его или выдайте вручную. Просите покупателей отправлять точную сумму из кошелька. |
| Платёж в TON не найден | Комментарий не указан или изменён | Так же, как выше. С TON Connect кошелёк подставляет комментарий сам. |
| `aimarket doctor` сообщает о приватном адресе | `url` в `node.toml` — не ваш публичный домен | Сгенерируйте `node.toml` заново (шаг 9) с `--url https://<домен>`. |
| `node` не стартует: `node.toml` — это папка | Compose создал её, потому что файла не было | `rmdir node.toml`, сгенерируйте файл (шаг 9), запустите снова. |
| Тестовый платёж отклонён: `402 … self_send_not_allowed` | Вы платили с адреса самой витрины `PAY_TO_EVM`; фасилитатор не принимает оплату самому себе | Платите с другого кошелька. |
| В логе узла `bazaar … resource must start with 'https://'` | `PUBLIC_URL` на http (локальный тест) | На тестовом узле ничего делать не надо; в боевой установке `PUBLIC_URL` — ваш домен на https. |
| Магазин или узел останавливается при старте: `…prices.csv, line N: …` | Строка прайс-листа не читается | Исправьте эту строку; `docker compose run --rm rails node bin/esim-rails.mjs prices /config/prices.csv` проверит весь файл. Затем `docker compose restart store rails`. |
